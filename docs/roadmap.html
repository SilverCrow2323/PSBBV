The build order

One milestone at a time.

The cross-build and package internals are verified. Physical Vita validation remains a separate gate.

CI verified · device test pending

Phase 0 — Native foundation

VitaSDK/CMake, libvita2d, Home navigation, front touch, application menu and branding are in source. Vita Build #83 produced a VPK whose package contents and LiveArea PNGs were inspected. Physical Vita testing remains open.

Next

Phase 1 — UI foundation

Reusable components, transitions, focus restoration, configurable button mapping, asset cache and measured frame pacing.

Planned

Phase 2 — Local content model

Typed metadata, safe discovery, empty/loading/error states, sorting and filters. Read-only first; destructive management comes only with proper safeguards.

Planned

Phase 3 — Channel modules

Games, Applications, Network, Media, Downloads and System. Each needs a real data source, a failure model and documented offline behavior.

Later

Phase 4 — Polish & release

Settings, localization, finished LiveArea art, compatibility testing, release notes and reproducible packages. No stable label until hardware says yes.

🚦
Release rule: green is not gold

A CI build proves the code cross-compiles and packages. It does not prove the VPK installs, launches, survives suspend/resume or feels good in your hands.

Done means done

Release gates

Build gate

Reproducible toolchain, successful VPK artifact, recorded SDK version and checksum.

Device gate

Install, startup, input, suspend/resume, performance and clean exit verified on real hardware.

Product gate

Implemented features work; placeholders are clearly labelled; no fake success states.

Release gate

Title ID confirmed, changelog written, install/update/uninstall path tested and docs updated.
